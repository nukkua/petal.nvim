1. INTRODUCTION                                                        *petal*

petal shows a magit-style status buffer and runs every git command async
through the git CLI. Pull requests go through `gh` (https://cli.github.com).

Requirements: Neovim 0.12+, `git`. Optional: `gh` for pull requests,
fidget.nvim for progress spinners.

Nothing is lost by accident: discarding tracked changes or a hard reset first
saves a backup stash ("petal backup HH:MM:SS"), and discarded untracked files
are moved to `.git/petal-trash/` instead of being deleted.

==============================================================================
2. SETUP                                                         *petal-setup*

`setup()` is optional. These are the defaults:
>lua
  require("petal").setup({
    reviewers = {},
    base_branches = { "origin/develop", "origin/main" },
    recent = 10,
    height = 12,
    commit_suggest = nil,
    mappings = {},
  })
<
Options are merged one level deep: a list or table you pass replaces the
default instead of being merged into it.

reviewers                                              *petal-opt-reviewers*
  List of GitHub logins offered when creating a PR. Empty: never asks.

base_branches                                      *petal-opt-base_branches*
  Tried in order to find the integration branch, used by the "merged into"
  PR line and by |petal-diff| "Branch vs base". Falls back to `origin/HEAD`.

recent                                                    *petal-opt-recent*
  Number of commits in the "Recent commits" section.

height                                                    *petal-opt-height*
  Height of the bottom popups and pickers.

commit_suggest                                    *petal-opt-commit_suggest*
  Command (argv list) for |petal-commit-suggest|.

mappings                                                *petal-opt-mappings*
  Key overrides for the status buffer, see |petal-mappings|.

==============================================================================
3. USAGE                                                         *petal-usage*

                                                                      *:Petal*
:Petal                  Open the status buffer for the repo of the current
                        directory. Outside a repo it offers `git init`.
:Petal {args}           Run `git {args}` and show its output, e.g.
                        `:Petal log -5`.

                                                                    *:DiffOff*
:DiffOff                Close the diff opened with `d` and go back to the
                        status.

Lua: `require("petal").open()`, `require("petal").command("log -5")`.

Popups list their actions; `-` followed by a key toggles an argument (it is
remembered per popup), `q` or <Esc> closes. Actions run on the item under the
cursor, or on a visual selection where that makes sense (stage, discard,
cherry-pick, ...).

4. KEYS                                                           *petal-keys*

Press `?` in the status buffer for this list with your own |petal-mappings|.
The action name is what |petal-mappings| uses.

                                                               *petal-actions*
Key     Action           Does ~
`$`     history          Log of every git command petal ran
`A`     cherry_pick      Cherry-pick popup
`b`     branch           Branch popup
`B`     bisect           Bisect popup
`c`     commit           Commit popup
`D`     diff_range       Diff popup, see |petal-diff|
`f`     fetch            Fetch popup
`l`     log              Log popup (branch, all, file, reflog)
`M`     remote           Remote popup
`m`     merge            Merge popup
`O`     pr               Pull request popup, see |petal-pr|
`p`     pull             Pull popup
`P`     push             Push popup
`Q`     command          Run a git command
`r`     rebase           Rebase popup
`t`     tag              Tag popup
`v`     revert           Revert popup
`X`     reset            Reset popup
`Z`     stash            Stash popup
<C-s>   stage_all        `git add -A`
`K`     untrack          Untrack the file(s)
`s`     stage            Stage file, hunk or selected lines
`S`     stage_unstaged   `git add -u`
`u`     unstage          Unstage file, hunk or selected lines
`U`     unstage_all      Unstage everything
`x`     discard          Discard file, hunk or selected lines
`d`     diff             Vimdiff of the file vs HEAD
`e`     merge_mode       Resolve a conflicted file (ours | theirs above)
<C-r>   refresh          Refresh
<CR>    goto             Open the file at that line, or the commit/stash
`za`    toggle_fold      Toggle fold
`zo`    open_fold        Open fold
`zc`    close_fold       Close fold (on a closed file: its section)
`zR`    open_all         Open all
`zM`    close_all        Close all
`?`     help             Help popup
`q`     close            Close the status

Log views get the popup keys (`$` to `Z` above) plus goto and help; commit and
diff views also get the fold keys.

In the commit message buffer:
<C-c><C-c>              Save and commit
<C-c><C-k>              Abort
<C-c><C-s>              Accept the suggested message |petal-commit-suggest|

==============================================================================
5. MAPPINGS                                                   *petal-mappings*

`mappings` maps a key to an action name from |petal-actions|, or to `false`
to remove the key. A key you set replaces its default, other defaults stay.
>lua
  require("petal").setup({
    mappings = {
      x = false,                -- no discard on x
      ["<leader>x"] = "discard", -- discard moves here
      ["<Tab>"] = "toggle_fold",
    },
  })
<
An unknown action name is reported once with a warning, and by
|petal-health|. Set mappings before opening the status for the first time.

==============================================================================
6. DIFFS                                                          *petal-diff*

`d` on a file opens a vimdiff of the worktree against HEAD; |:DiffOff| closes
it. `D` opens the diff popup:

  `b`  Branch vs base   what the branch adds: `<base>...HEAD`, base from
                       |petal-opt-base_branches|
  `r`  Branch vs ref    the same against a branch you pick
  `c`  Range            any `git diff` arguments, e.g. `main..feature`
                       (prefilled with `<commit>..HEAD` on a commit row)

The result opens in the same view as a commit: files with +/- counts and
foldable diffs, <CR> on a diff line opens the file at that line.

==============================================================================
7. PULL REQUESTS                                                    *petal-pr*

Needs `gh` logged in (`gh auth login`). The status shows the PR of the current
branch under "Push" (state, mergeable, review, CI). `O` opens the PR popup:

  `p`  Status            PR summary of this branch
  `l`  List              open PRs, <CR> copies the URL
  `o`  Open              open this branch's PR in the browser, copy URL
  `c`  Checkout          pick a PR and `gh pr checkout` it
  `d`  Diff              this branch's PR diff (`gh pr diff`) in the diff view
  `k`  Checks / CI log   checks of this branch's PR, failures first. <CR> on
                        a failed GitHub Actions job shows the log of its
                        failed steps, any other check opens in the browser
  `n`  Create            `gh pr create --fill`, asking for reviewers when
                        |petal-opt-reviewers| is set
  `x`  Close             close this branch's PR

==============================================================================
8. COMMIT MESSAGE SUGGESTIONS                           *petal-commit-suggest*

Set `commit_suggest` to a command that reads the staged diff on stdin and
prints a commit message. It starts when the commit buffer opens; the
suggestion shows as ghost text while the message is empty and <C-c><C-s>
accepts it (pressed early, it goes in when it arrives). Closing the buffer
stops the command.
>lua
  require("petal").setup({
    commit_suggest = { "claude", "-p", "--model", "haiku",
      "Write one Conventional Commits message for the staged diff on stdin. "
      .. "Output only the message." },
  })
<
Any CLI that works this way can be used, e.g. `llm` or `ollama run`.

==============================================================================
9. HIGHLIGHTS                                               *petal-highlights*

Every group is defined with `default = true`, so a colorscheme can override
it. Git groups are named `Git*` (e.g. `GitSectionHeader`, `GitDiffAdd`), PR
groups are `PrOpen`, `PrMerged`, `PrClosed`, `PrDraft`, `PrWarn` and
`PrBranch`.

==============================================================================
10. HEALTH                                                      *petal-health*

`:checkhealth petal` checks the Neovim version, `git`, `gh` and its login,
fidget.nvim, `commit_suggest` and `mappings`.
